# n3 - the signer process

`src/signer/server.ts`: `startSigner(socketPath, wallet, policy, now?)` returning `SignerServer`.

Two operations, `address` and `sign`. There is deliberately no operation that takes a digest, so
the socket cannot be used to obtain a signature over caller chosen bytes. An unrecognised op is
refused with `unsupported_op` rather than being interpreted generously.

Socket mode is 0660 rather than the daemon's 0600, because the signer and the daemon run as two
different users sharing a group. That is what stops the daemon reading the signer's memory.

7 tests. The load bearing one asserts a signature obtained through the socket is byte identical to
one the local key produces directly, because a transport that subtly alters the payload yields a
valid signature over the wrong payment and no other test would notice.
