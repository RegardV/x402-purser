# n6 - daemon wired to the signer

`purser run --signer-socket PATH` connects to the signer instead of prompting, so the key never
enters the daemon process. Without the flag it still reads a key from stdin, which is the weaker
development configuration and is documented as such.

`src/index.ts` exports the signer surface. The README's key custody section now states the stronger
claim precisely, and the "does not claim" list gained two entries that the split does not fix: the
signer still holds the key in memory rather than in hardware, and a compromised daemon can still
cause payments that were already inside policy, because authorising payments is its job.

`test/split-e2e.test.ts` proves the daemon pays correctly with the key in another process and the
ledger records 1000 committed, so the split cannot silently break payment.
