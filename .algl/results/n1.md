# n1 - the threat model

`docs/superpowers/specs/2026-08-16-threat-model.md`. Seven adversaries (A1 hijacked agent, A2
malicious seller, A3 compromised daemon, A4 compromised signer, A5 local process in the group, A6
root, A7 holder of a leaked authorization), each with an explicit loss bound rather than a control
description.

The document exists because Purser was built by discovering adversaries one at a time, which has no
end state: no software component we can add is trustworthy by construction. The question it answers
instead is what bounds the loss when the trusted component is the one that fails.

Central conclusion: only the hot wallet balance bounds loss, because the token contract will not
transfer what is not there. The signer's window and the authorization horizon reduce blast radius
and duration; they do not bound. That distinction is what the earlier documents got wrong.

Gate note: the checker initially failed on the trust boundaries row "| Agent to daemon" because it
matched any row starting "| A". Tightened to adversary IDs. The gate was wrong, not the document.
