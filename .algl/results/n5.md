# n5 - the binary and the hardening

`src/signer/cli.ts` is the `purser-signer` binary: key on stdin, policy from coarse flags, then
`startSigner`. `package.json` gains the second bin entry.

`deploy/purser-signer.service` carries the hardening that makes the split worth doing.
`PrivateNetwork=yes` plus `RestrictAddressFamilies=AF_UNIX` and `IPAddressDeny=any` mean the process
holding the key has no route off the machine at all, so even arbitrary code execution inside it
cannot exfiltrate the key. `MemoryDenyWriteExecute`, `ProtectProc=invisible` and an empty
`CapabilityBoundingSet` remove the rest.

The key reaches it through `LoadCredentialEncrypted` rather than a flag or an environment variable,
sealed to the machine and decrypted only into the unit's private credential directory.

`deploy/README.md` includes the two commands that prove the isolation rather than assuming it:
reading the signer's `/proc/pid/mem` as the daemon user must fail, and `nsenter -n` must show no
usable interfaces. It also says to read `systemd-analyze security`, because systemd silently
ignores misspelled directives.
